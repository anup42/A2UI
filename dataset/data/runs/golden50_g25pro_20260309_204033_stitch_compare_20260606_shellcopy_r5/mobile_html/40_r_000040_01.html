JavaScript Variable Declaration: var, let, and const

This guide explains the key differences between the var, let, and const keywords in JavaScript, focusing on their scope, hoisting behavior, and re-assignment rules. Understanding these distinctions is fundamental to writing modern, predictable, and bug-free JavaScript code. let and const, introduced in ES6 (2015), are now the standard for variable declaration.

Core Characteristics and Behavior

The primary differences between var, let, and const lie in their scoping rules, how they are handled by the JavaScript engine before execution (hoisting), and whether their values can be changed after declaration.

var

  • Scope: Function-scoped. A variable declared with var is accessible anywhere within the function it is defined in, regardless of block constructs like if statements or for loops. If declared outside any function, it is globally scoped.
  • Hoisting: var declarations are hoisted to the top of their scope and are initialized with the value undefined. This means you can access a var variable before its declaration without an error, though its value will be undefined.

let

  • Scope: Block-scoped. A variable declared with let is only accessible within the block ({...}) it is defined in. This includes loops, if statements, and standalone blocks.
  • Hoisting: let declarations are hoisted but are not initialized. Accessing a let variable before its declaration results in a ReferenceError. This period between the start of the block and the declaration is known as the "Temporal Dead Zone" (TDZ).

const

  • Scope: Block-scoped. Same as let, a const variable is only accessible within the block it is defined in.
  • Hoisting: Same as let, const declarations are hoisted but not initialized, creating a Temporal Dead Zone.
  • Re-assignment: A const variable cannot be re-assigned after it has been declared. It must be initialized at the time of declaration. Note that for objects and arrays, this means the reference cannot be changed, but the contents of the object or array can be modified.

Critical Use Case: Asynchronous Loops

This example demonstrates a common scenario in asynchronous programming where the choice of keyword is critical. The goal is to log the numbers 0, 1, and 2 after a short delay.

Problem with var

Because var i is function-scoped, there is only one i variable shared across all loop iterations. By the time the setTimeout callbacks execute, the loop has already finished, and the value of i is 3.

``javascript for (var i = 0; i < 3; i++) { setTimeout(() => { console.log(i); // Outputs: 3, 3, 3 }, 100); } ``

Solution with let

Using let creates a new, block-scoped i for each iteration of the loop. Each setTimeout callback captures a different i with the value it had during that specific iteration, leading to the expected output.

``javascript for (let i = 0; i < 3; i++) { setTimeout(() => { console.log(i); // Outputs: 0, 1, 2 }, 100); } ` This behavior makes let` essential for writing correct and intuitive loops involving closures or asynchronous operations.
