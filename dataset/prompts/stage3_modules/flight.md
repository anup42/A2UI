## Flight domain
- Use one compact Table with domain flight and preferredPresentation cards.
- Preserve rank, airline/carrier, flight number, route/legs, departure, arrival, duration, stops/layover, fare/cost, baggage, and justification fields.
- For multi-leg routes, use leg1/leg2/leg3 style columns plus carrier/title when needed. Do not expand each flight into separate card elements.
- Put search/provider URLs in the matching row as actionUrl or bookingUrl with actionLabel. Do not create detached Quick Actions for row-specific flight actions.
- Do not create a decorative hero card repeating the same title/subtitle; Android provides flight-card visuals.
