TEDY flat-spec is the intermediate representation used by the project for response-to-mobile-UI generation. The spec is a single JSON object with exactly three core top-level fields: root, state, and elements.

root: a string id that names the entry element. Rendering starts from this id.
state: a JSON object containing reusable structured data such as table rows, forecasts, flights, itinerary days, recommendation items, source URLs, action URLs, and asset references. State keeps repeated data compact and prevents the model from expanding every table cell into many UI nodes.
elements: a flat map from element id to component object. Each component has a type, props, children, and optional repeat or on/action handlers. Children are ids, not nested component objects, so the contract can validate references and repair missing or dangling ids.

Supported semantic components include Stack, Row, Column, Card, Text, Table, Image, Icon, Button, Tabs, Formula, CodeBlock, ConsoleLog, EmailPreview, Divider, and form controls. The spec intentionally describes semantic UI intent rather than pixel-level layout or HTML/CSS. A compact Table uses props.columns and props.statePath or props.rows. The Android renderer then chooses the best presentation: weather cards, flight cards, booking cards, comparison cards, timeline cards, key-value panels, horizontal tables, or landscape/tablet true tables.

Validation checks root existence, component type validity, child reference validity, repeat state paths, table columns and rows, action shape, media references, and unsupported components. Normalization repairs common LLM mistakes, hoists aliases, compacts expanded table trees, prunes empty/default props, and emits diagnostics. The same flat-spec output is used for rendering, scoring, dashboard inspection, and response-to-IR model training.
