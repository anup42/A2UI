# Bixby50 repair and renderer change review

Read-only source review, 29 September 2026. Scope: the SDK `GenUiCompiler`, `A2uiExpressGeneralRepair`, native flat table/entity-card/text presentation changes, and their focused tests. This review did not edit app or pipeline code. The saved-corpus findings remain in [REPORT.md](REPORT.md); they are historical artifact evidence, not a fresh model score.

| Concern | Final code and focused evidence | Review result |
|---|---|---|

Tests cover nonempty repeat plus orphan, nested table plus orphan, and unused state that correctly forces salvage. | Resolved in focused tests. |

The new metric mapper partitions every nonblank source cell into title, value, or detail cells, and both paths display the table title. SDK and Android paths were inspected, the final SDK suite passed, and the installed-app [BXP-018 capture](../device/after/historical50/BXP-018/initial.png) displays all five rows with heading, artist, date, rank, and chart fields. | Resolved for present generated cells; malformed dates in raw output remain a separate source-fidelity issue. |

Contract checks: strict `compile()` and the default `compileWithRepair` arguments remain unchanged; generated graph repair is opt-in. The compiler still reports generated salvage as `GENERATED_DSL_REPAIR`, source-derived fallback as `SOURCE_TEXT_FALLBACK`, and strictly accepted input as `NONE`. Its source-text integrity gate still checks generated candidates before returning them. The renderer keeps an explicit table request ahead of heuristic card routing.

Known limits: graph repair can only reconnect facts already generated. It cannot restore omitted caveats, missing citations, changed numbers, or lost units (see BXP-001, BXP-009/012, and the historical BXP-029/032/047 cases). The orphan attachment and direct-root overlap rules infer author intent from graph structure; ambiguous duplicate wording still merits device/source inspection. Non-explicit one-column rendering omits blank row values from display while retaining them in the resolved model. The focused renderer assertions inspect model/card mapping, not pixels; device screenshot review is separate.
