# v10 training and GenUICraft inference pipeline review

Scope: read-only review of the checked-in **base v10** training bundle, the current Golden training/deployment launcher, the direct remote E2B LoRA recipes, and the trained GenUICraft SDK profile. The launchers now expose optional `rare_components` or teacher-generated `semantic` augmentation, but both default to `none` (`training/scripts/run_golden_training.py:32-38`; `training/scripts/run_official_mobile_pipeline.py:56-62`; `training/src/ir_training/pipeline/golden_training.py:71-77`; `training/src/ir_training/pipeline/official_mobile.py:92-98`). The corpus measurements here precede any optional augmentation: we did not execute generation or audit future augmented rows. This report does not measure all v10 rows, model accuracy, GPU behavior, or export parity. The companion corpus audit owns population counts and semantic defects. References below are to this checkout on 2026-09-26.

## Decision-relevant findings

1. **Current launcher changes the v10 supervision prompt before training.** The source archive is not already in the deployed training format. For the first train row, `archive-train-017913-680b05c2ffc96895`, the saved source system message is 4,766 characters and its saved `metadata.shared_prompt.contract_sha256` is `00a5af656e875f8bbe7b15e000efb4ef751f8e6223da3608648d20e94b296bf5`. The current system message is 10,553 characters, with contract `005ef700eee29a4429c895ac6c86580003c43d0ad35e67cbb92a9d4cf0e8c1d2`. Current preparation first validates the old row, then replaces the system/example scaffold and final task with the new shared prompt (`training/src/ir_training/data/shared_prompt.py:154-173`), and only then measures tokens and quarantines overlong rows (`training/src/ir_training/data/express_preparation.py:458-473`). On the available local SentencePiece proxy, this row's archived supervised sequence is 3,265 tokens; the current-prompt sequence is 4,757, above the launcher's 4,096 limit (`structure_rows.jsonl`, train line 1). **Therefore raw v10 token lengths and raw row counts are not a training-ready acceptance count.** Measure the *normalized, serialized* row with the exact selected HF tokenizer. This is a verified contract change and a likely large retention risk, not a finding that the source row itself is invalid.

2. **URL/media masking has no equivalent trained SDK serving path.** v10 archive row 2, `archive-train-146903-ff887f40fc6bb55d`, stores nine URL-map entries; `[ICON_URL_1]` in its response maps to `https://cdn.jsdelivr.net/npm/bootstrap-icons@1.11.3/icons/translate.svg`. Recovery explicitly masks source and target references with a source-identity policy, proving exact restoration (`training/src/ir_training/data/archive_recovery.py:912-950`; `training/src/ir_training/data/url_preprocess.py:77-104,108-122,149-165`). Python evaluation carries and restores the map for source/reference presentation (`training/src/ir_training/eval/generate.py:224-254,316-320`). The SDK trained converter passes `request.text` directly to `contract.prompt()` and then compiles the output (`GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/GenUiTrainedConverter.kt:53-71`); it has no row URL map. Its safe-content policy explicitly accepts a correctly shaped placeholder as a URL (`GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/internal/security/SafeContentPolicy.kt:95-107,130-158,317-318`). Thus raw production URLs and mapped training placeholders follow different input/output paths. A model failure or broken link rate is **not measured here**; a generated-only raw-URL test should establish it. Model training alone cannot teach the SDK which original URL to substitute for an arbitrary generated `[ACTION_URL_n]` without a request-scoped binding.

3. **The training tokenizer for a new run is not locally proven.** The available `tmp/e2b_mobile_20260921/tokenizer.model` hashes to `e594c8a90eb08d8bda498ff4747977dc827ae0c3c56b5c0d41a605a22d02ef03`, matching the `SP_Tokenizer` section recorded in `tmp/e2b_mobile_20260921/model_audit.json`. That audit identifies its package as `C:\Users\anupk\Downloads\asset_238\gemma4_e2b_a2ui_mobile.litertlm`, not a verified newly trained v10 model. The package metadata has BOS ID 2 and stop IDs 1, 50, 106; raw SentencePiece encoding of literal `<bos>` does not itself insert control ID 2 (`tmp/e2b_mobile_20260921/model_audit.json:65-91,166-170`). Earlier 50 Bixby prompt counts of 3,031–3,759 are a *proxy* for budgeting, not the new training tokenizer identity. The launcher requires a local dense HF model/tokenizer (`training/src/ir_training/pipeline/golden_training.py:166-170,235-238`), records vocabulary/chat-template hashes and token IDs in the prepared manifest (`training/src/ir_training/data/express_preparation.py:522-532`), and verifies the same loaded tokenizer/template at SFT start (`training/src/ir_training/train/prepared_binding.py:14-43`). Preserve those fresh receipts before citing any exact token acceptance number.

4. **Older remote v10 recipes do not identify the current bundle or enforce the current review workflow.** The five `gemma4_e2b_a2ui_express_lora_remote_full*.yaml` recipes point to distinct `/home/k_anup/.../prepared_v10_express*` directories (`training/configs/models/gemma4_e2b_a2ui_express_lora_remote_full.yaml:1-3`; `_v3.yaml:1-3`; `_v4.yaml:1-3`; `_v5.yaml:1-3`), set `max_seq_length: 4096`, use the HF backend, and disable Golden evaluation (e.g. `_v5.yaml:24-37,61-62`). They do not set `run.prepared_manifest_required`. In `train_sft`, an absent manifest is allowed unless that flag is true (`training/src/ir_training/train/sft.py:191-213`; `training/src/ir_training/train/prepared_binding.py:14-25`). This is a recipe/provenance risk, not proof those remote directories are bad; their contents and training receipts are unavailable here. The current launcher does set `prepared_manifest_required=True` through `prepare_review_training.py:176`, binds the prepared chat-template options at line 245, and checks the prepared split and benchmark contracts at lines 238-245.

5. **Bixby50 is reserved from rows and checkpoint selection, but not pristine for prompt-level generalization claims.** The current launcher loads reserved Golden/Bixby identities and response hashes, filters them before training, and marks Bixby50 `final_only_holdout` (`training/src/ir_training/pipeline/golden_training.py:187-203,255-275,321-355`; `training/src/ir_training/data/audit_filter.py:19-44,71-83`). A prior on-device study explicitly tuned prompts on Bixby50 and calls those results a development study rather than a held-out estimate (`GenUICraft/experiments/gemma_prompt_study_20260918/README.md:3,15-19`). This is prior prompt-development exposure, **not evidence that Bixby source rows leaked into SFT**. Report Bixby50 checkpoint selection separately from independent prompt/workflow generalization.

6. **The current streaming repetition guard can cut off one valid training pattern.** Train line 6,416 (`archive-train-109871-f518eb549644b798`) is a structurally valid 22-child `Column`: `l=Column([m,n,o,p,q,r,s,t,u,v,w,x,y,z,aa,ab,ac,ad,ae,af,ag,ah],"sm")`. The SDK scans unfinished `Column` child-reference lists and stops after 20 sequential alphabetic IDs, here `m` through `af` (`GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/provider/GenUiOutputRepetitionGuard.kt:26-30,49-71,81-116`). `Gemma4Streaming.kt:29-56` applies that guard to every cumulative native delta and cancels on a hit; `Gemma4Runtime.kt:155-185` always uses that async path, even without a UI streaming observer, and reports `REPETITION_LIMIT`. This is a **conditional serving false-positive risk**: a native callback exposing that prefix before `</a2ui>` will stop a valid-looking generation, whereas a single callback already containing the closing tag bypasses the guard (`GenUiOutputRepetitionGuard.kt:27`). Existing tests cover the 20-ID threshold and complete-document bypass (`GenUiOutputRepetitionGuardTest.kt:20-33,43-46`); no device-generation failure was observed or claimed.

## What the current launcher actually does

- `training/data/train/v10/bundle.json:2-14` names `full_data_archive_recovered_v10` as `training_inputs_only`; `training/data/train/v10/README.md:1-4` records 91,115 train and 1,862 validation rows. That README says restoration preserves bytes, order and metadata without quality repair and calls the bundle an offline candidate with known manual-review issues. The current launcher consumes restored `train.jsonl` and `val.jsonl` with `--input-dir`, not the `.gz` parts (`training/scripts/run_golden_training.py:20-22`; `training/src/ir_training/pipeline/golden_training.py:169-170,329-330`).
- The launcher creates the *current* full production shared prompt from `dataset/prompts/genui_gen_mobile_a2ui_express_v1.md` plus one worked user/model example (`training/src/ir_training/data/shared_prompt.py:32-58`; `training/src/ir_training/data/chat_templates.py:44-90`). It rejects drift from the live source prompt for a fresh preparation (`training/src/ir_training/data/shared_prompt.py:107-117`; `training/src/ir_training/pipeline/golden_training.py:255-261`). `python GenUICraft/tools/sync_trained_prompt.py --check` passed with contract `005ef700...` on this checkout; the SDK asset and current builder match as JSON.
- The source filter checks strict Express, source identity and reserved cohorts, removes exact normalized-source/semantic-target duplicates, and reports same-source/different-target instances rather than silently picking one (`training/src/ir_training/data/audit_filter.py:71-83,90-103,129-159`). Preparation uses `serialize_checked` to decode the target, reject unreachable definitions, validate wire form, reorder assignments root-first, and prove decoded graph equality plus semantic hash (`training/src/ir_training/data/express_preparation.py:107-169`). It also checks assistant/target aliases and final user response binding (`:192-250`). This is structural and reference integrity, not complete factual fidelity.
- With the local HF tokenizer, preparation renders full supervised chat and generation prompt using `apply_chat_template(..., enable_thinking=False)`. It requires the prompt string to be an exact prefix of the supervised chat; tokenizes prompt and completion separately with `add_special_tokens=False`; quarantines a complete train/val row above 4,096 supervised tokens or 4,096 prompt tokens (`training/src/ir_training/data/express_preparation.py:260-280,458-473`; `training/src/ir_training/pipeline/golden_training.py:368-375`). The Golden launcher still defaults to a 4,096-token supervised sequence and prompt limit, 2,048 generated tokens, and checks against E2B's 8,192-token context (`training/src/ir_training/pipeline/golden_training.py:40-53,156-165`; `training/scripts/run_golden_training.py:45-47`). The separate official mobile pipeline still defaults to `max_seq_length=4096`, with an independent 5,120-token evaluation prompt limit (`training/src/ir_training/pipeline/official_mobile.py:79-81`; `training/scripts/run_official_mobile_pipeline.py:41-45`). The preparation code deliberately excludes final evaluation references from the supervised-sequence limit but still checks their generation prompts (`training/src/ir_training/data/express_preparation.py:460-463,521`).
- The review fit command uses the checked `prepared` directory by default, switches to `augmented` only when augmentation is explicitly selected, and writes `prepared_manifest_required=True` (`training/src/ir_training/pipeline/golden_training.py:385-396`; `training/scripts/prepare_review_training.py:176`). `ModelAdapter.format_example` applies the loaded tokenizer’s template for both full chat and generation prefix (`training/src/ir_training/models/base.py:112-125`). The HF path builds `input_ids = prompt_ids + completion_ids`, `labels = [-100] * prompt_length + completion_ids`, refuses empty turns and any overflow, and does no truncation (`training/src/ir_training/train/sft.py:1427-1475`). The default adapter sets right padding (`training/src/ir_training/models/base.py:93-98`); the collator preserves provided labels and pads labels with `-100` (`training/src/ir_training/train/sft.py:2927-2969`). Checked shifted CE uses `ignore_index=-100` (`:2832-2857`). This path has **no sample packing**; the optional TRL path can set packing but the E2B review and remote configs select HF (`training/src/ir_training/train/sft.py:491-509,534-547`).
- SFT supervises the template-rendered assistant suffix and does **not** append an EOS token itself (`training/src/ir_training/train/sft.py:1427-1468`). The available E2B package's embedded template puts `<turn|>` after the assistant message (`tmp/e2b_mobile_20260921/llm_metadata.json`), and package metadata lists ID 106 among stop tokens (`tmp/e2b_mobile_20260921/model_audit.json:71-85`). The actual training HF tokenizer/template must be verified from its prepared manifest before concluding that its terminal labels are identical. Generation EOS IDs are preserved from model/generation/tokenizer configurations (`training/src/ir_training/generation_policy.py:46-81`), while the Express closing sentinel is a separate decode stop (`:84-113`). A missing closing tag in a target is rejected by strict preparation; a model can still stop early at runtime.

## Inference parity boundary

The trained SDK profile pins the same shared JSON contract, adds system plus one user/model example, appends `task_prefix + response.trim()` as the final user turn, disables thinking, uses temperature 0, and budgets 8,192 context/2,048 output (`GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/GenUiTrainedConverter.kt:115-143`; `GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/GenUiSession.kt:23-47`). It hardcodes the profile label `trained_e2b_v10_w4` and supplies a text-only Android chat-template override plus an expected rendered prompt. The native runtime checks its full first-turn rendered bytes against that expected prompt before generation (`GenUiTrainedConverter.kt:116,128-165`; `GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/provider/Gemma4Runtime.kt:128-153`). An earlier offline audit of the extracted `asset_238` package found byte parity across 50 Bixby text prompts under `enable_thinking=false` (`tmp/e2b_mobile_20260921/model_audit.json:163-204`), but its reuse assessment says the unchanged converter would mislabel that supplied artifact as v10-W4 and override its richer embedded template (`:209-213`). The audit also records no embedded new-run shared-prompt snapshot, prepared manifest, training config, checkpoint receipt or source commit (`:215-219`). Byte parity with current code is therefore **not proof that a particular model checkpoint was trained on this new normalized v10 dataset**; match the Android override and checkpoint/export receipt before using that profile label as provenance.

The SDK converter defaults to source-integrity checking and a deterministic source-text fallback; it records repair/fallback kind in warnings (`GenUiTrainedConverter.kt:24-29,65-105`). For model-quality measurement, use generated-only mode and report raw strict validity, generated repair, fallback and fidelity separately. A rendered success through fallback does not demonstrate that the model learned the target.

The dataset's `Table.domain` values `formula`, `playlist`, and `restaurants` are supported by the current Android native renderer, despite the shorter domain-hint list in the repository notes. The current capability set explicitly includes all three (`GenUICraft/genuicraft/src/main/java/com/samsung/genuicraft/sdk/internal/renderer/flat/capability/GeneratedRendererCapabilities.kt:37-39`); direct and container Table extraction accept the explicit supported domain (`flat/compose/FlatDirectTableRender.kt:170-181`; `flat/compose/table/FlatTableModelExtraction.kt:292-306`). The renderer has restaurant and playlist card modes (`FlatDirectTableRender.kt:188-201`) and formula-specific table-shape handling (`FlatTableModelExtraction.kt:183-187`). These domain labels alone are **not** a schema or runtime compatibility defect. Visual/factual correctness of individual Table rows remains a separate question.

## Local tokenizer accounting cross-check

`pipeline_token_probe.py` checks a deterministic 503-row sample: the first 128 of each split, spaced rows through both splits, and the 22-child train case. All 503 rows normalized with the current shared prompt and root-first `prepare_row`. For the available local SentencePiece model, the root corpus scanner's raw-target/current-prompt concatenated count exactly matched the canonicalized, separately encoded prompt plus assistant suffix on every sampled row. Prompt outer trim, target reserialization, and the prompt/completion token boundary each had a zero-token delta, so the sample had no threshold disagreements at 4,096, 6,144, 8,192 sequence tokens or 2,048 target tokens (`pipeline_token_probe.json`; comparison method in `training/src/ir_training/data/express_preparation.py:260-280`, scanner at `training/reports/v10_full_audit_20260926/audit_structure.py:35-37,60-67`). This validates the **local proxy method on these 503 records**, not the exact HF tokenizer used in a future run or a proof that no other archive row differs. The actual prepared manifest remains the authority for acceptance and loss-mask lengths.
